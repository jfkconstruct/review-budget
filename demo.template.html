Four reviewer hours can avert a sixth of your queue’s damage, or half of it.

Same hours, same queue, same people. The only difference is the order the cases are opened in. Drag the dial and watch which cases each policy puts in front of a human.

What the queue is, plainly: 398 questions a language model answered on its own, from a public benchmark that ships a correct answer for every row. The answer key is the whole reason a number exists here. A demo run on your own documents would output a confident ranked list nobody could check, which is the failure this page argues against.

What this does not prove
Costs are invented Benchmark rows carry no dollar value. Three shapes run and all three are on the dial, because the shape of the cost distribution is a claim, not a measurement.
Direction, not magnitude
The interval has a knob in it Replicate count is a setting, so these ranges narrow without a single new labelled case arriving. They describe resampling of this 398-case queue and nothing wider.
The reviewer is perfect Every wrong case a human opens is assumed fixed. That is an upper bound, applied identically to all five policies, so it flatters the rows equally.
One task, one benchmark 398 yes/no reading-comprehension questions. Nothing here has been shown to transfer to claims, tickets, or moderation without repeating the measurement on that data.
The lists are one draw The two columns above use a single cost draw, because an average of 2000 draws is not a list you can read. The numbers under “what the budget buys” are the 2000-draw bootstrap, never this one.

Every number on this page comes out of python budget.py --replicates 2000, which calls no API and replays a stored run. The write-up with the intervals and the sign tests is QUEUE.md; the bake-off behind the probabilities is RESULTS.md.
